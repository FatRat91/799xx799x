## 出題比率と重視する判断

| 公式領域 | 比率 | 何を判断・説明できるようにするか |
|---|---:|---|
| 端末の管理・維持 | 25–30% | Autopilotの方式とモード、ESP、構成プロファイルと割り当て、Intune Suite、遠隔操作、診断の使い分け。Windows 365 Cloud PCのプロビジョニングも含む。 |
| 端末の基盤準備 | 20–25% | Entra登録・参加とIntune登録、Windowsの自動登録、Apple・Androidの登録、グループ、RBAC、準拠と条件付きアクセス。 |
| 端末の保護 | 15–20% | BitLocker、Defender、ASR、Firewall、ベースライン、App Control for Business。機能更新・品質更新・更新リング、Autopatch・Hotpatchもここ。 |
| アプリの管理・保護 | 15–20% | アプリの種類、配信の成否、対応するストア、アプリ構成・保護ポリシーと条件付きアクセス。 |
| 自動化・監視・レポート | 10–15% | Graph／PowerShellでの管理、レポート、Endpoint Analytics、Remediations、テナント正常性、IntuneのSecurity Copilotエージェント。 |

上位2領域の比率を足すと45–55%。Windowsで登録・展開・割り当て・状態確認をつなげて学ぶと、保護や配信のケースにも同じ考え方を使える。 [公式の全出題項目](https://learn.microsoft.com/ja-jp/credentials/certifications/resources/study-guides/md-102)

## 状況から引く

| こんな状況 | 選ぶもの・確認先 | 到達ライン |
|---|---|---|
| **社用Windowsをクラウドで管理したい** | Entra参加、Intuneへの自動登録、デバイスグループ | 個人端末のRegistered、クラウド参加のJoined、AD参加も保つHybrid Joinedを区別。Entraの端末IDとIntuneの管理登録を別々に確認できる。 |
| **新品PCを直送して初回セットアップしたい** | Windows Autopilot、デバイス準備、ESP | 要件から展開方式やモードを選ぶ。従来のAutopilotではOOBEから参加・登録・ポリシー／アプリ適用まで追い、ESPで止まった段階を説明する。 |
| **PCの設定を揃えたい。設定が届かない** | 構成プロファイル、設定カタログ、割り当て、フィルター | ユーザーとデバイスのどちらを対象にするか決める。グループ・除外・フィルターから対象を追い、設定単位の結果を確認する。GPO移行ではGroup Policy analyticsとADMXの役割も押さえる。 |
| **準拠した端末だけに業務アプリを使わせたい** | Intuneコンプライアンス、Entra条件付きアクセス | 最低OSなどの条件をIntuneが評価し、Entraの許可制御がその結果を使うと説明する。非準拠の項目と、サインインログのポリシー評価を確認できる。 |
| **端末を守り、脅威や暗号化の状態を見たい** | BitLocker、Defender AV／EDR、ASR、Firewall、App Control | 要件から保護機能を選ぶ。BitLocker回復キーの確認・ローテーション、MDEオンボード、MDEの端末リスク→Intune準拠→条件付きアクセスを説明できる。 |
| **Windowsのバージョンとパッチ適用を管理したい** | 更新リング、機能更新、品質更新、Autopatch、Hotpatch | 延期・再起動を管理する場面、対象バージョンを指定する場面、品質更新を急いで配る場面を区別する。配信の最適化と更新状況の確認先も押さえる。 |
| **アプリを配る。インストール済みなのに失敗表示** | Win32、LOB、Store、Microsoft 365 Apps。配信レポートとIMEログ | アプリの形式・配布先から方式を選ぶ。Win32では必要条件、検出、依存関係、置き換えと、必須・使用可能の割り当てを説明する。コマンドの実行結果と検出結果をそれぞれ確認する。 |
| **私物スマホの業務データを守りたい** | アプリ保護、アプリ構成、モバイル登録 | データ移動を制御するアプリ保護と、接続先などの初期値を入れるアプリ構成を選び分ける。対象アプリと条件付きアクセスも決める。社用ならApple ADE・Android Enterpriseの所有形態と登録方式を選ぶ。 |
| **PCの操作権限や管理者の権限を絞りたい** | Windows Hello for Business、LAPS、EPM、Intune RBAC、複数管理者承認 | サインイン、ローカル管理者パスワードの管理、個別ファイルの昇格、管理センターの権限、変更承認を使い分ける。ロール・スコープグループ・スコープタグの役割を説明する。 |
| **端末が失敗した。状態把握と是正を繰り返したい** | レポート、端末診断、デバイスクエリ、Remediations、Graph | 個別端末・全体傾向・テナント障害で確認先を切り替える。Remediationsの検出／修復、Graphでのデータ取得、Copilotの推奨を確認して判断する流れを説明する。 |

## 受験に向けた自己判定

公式の合格基準は**換算スコア700以上**。問題の難度を反映した点数で、必要な正答数は公開情報から特定できない。次の3点は、出題範囲から考えた準備の目安。 [公式の採点方法](https://learn.microsoft.com/ja-jp/credentials/certifications/exam-scoring-reports)

1. **Windowsの検証を1台で通す。** 登録、構成プロファイル、Win32配信、準拠、条件付きアクセスの評価を追う。成功1件と失敗1件で、理由と確認先を説明する。
2. **別条件のケースも解く。** 社用から私物へ、WindowsからApple／Androidへ、全社配信から試験グループへと条件が変わったら、何を変えるかを答える。
3. **公式の練習問題で初見の理由を説明する。** 選んだ答えの根拠を言い、間違えた領域はガイドの項目に戻る。Windows 365、Intune Suite、エージェント、非Windowsの範囲も確認する。 [公式の練習問題への入口](https://learn.microsoft.com/en-us/credentials/certifications/modern-desktop/#practice-for-the-exam)

あなたのMECMでの配信・検出やIntuneのEPM・EAMは、要件と適用結果を説明する練習にそのまま使える。先に手を動かすなら、実務で手薄なAutopilotと準拠＋条件付きアクセスから。
